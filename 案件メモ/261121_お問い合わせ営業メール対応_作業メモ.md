# 【神西衡機】お問い合わせフォーム｜営業・取材・掲載メールの切り分け

- 登録: 2026-11-21
- 公開: 2026-11-21（demo 確認後、本番へ反映）
- 対象: ローカル / demo / 本番

---

## 1. 対応内容

ホームページのお問い合わせに、売り込み・取材・掲載のメールが集中していた。種別「その他」を一律ではじくと、過去の実問い合わせ（分銅レンタル、請求再送、校正の人員、計量制度の質問）まで落ちるため、次の動きにした。

種別（セレクト）はそのまま。

- はかり・分銅等の販売について
- はかりの修理について
- はかり・分銅の検査について
- 特定計量器（はかり）の代検査について
- その他

「その他」を選んだときだけ、ラジオを出す。

- 分銅・ウエイトのレンタル
- これまでのご依頼についての連絡（見積・請求・日程など）
- 校正・点検の相談
- 計量器の検査や制度についての質問
- 上記以外（営業・ご提案、取材、掲載など）

| 選んだ内容 | 動き |
|---|---|
| 販売・修理・検査・代検査、および「その他」の上4つ | これまでどおり。管理者メール、問い合わせ一覧、連番、通常の自動返信、通常の完了文 |
| 「上記以外（営業・ご提案、取材、掲載など）」 | 管理者メールは送らない。一覧に残さない。連番は増やさない。自動返信と完了画面だけ、売り込み等は受けておらず担当者から連絡しない、という文面 |

導入文の直下に、赤い注意文を置いた。

> 商品・サービスの売り込み、取材、掲載のご提案などはお受けしておりません。計量器に関するご相談のみ対応しております。

URL の有無ではじかない。修理見積に Google ドライブの URL が入る依頼がある。

- ローカルの PHP は、このサイトのバーチャルホストだけ Homebrew の 8.5.13。MAMP の標準は 8.5.12 のまま。他のローカルサイトは変えていない。

- WordPress の自動更新は「メンテナンスリリースとセキュリティリリースのみ」にする方針。管理画面のその文言のリンクが切替。
- お問い合わせ CSS の読み込み版は `1.1.2`、JS は `1.1.0`（`inc/common_theme.php`）。

## 3. 本番へ置いたファイル

テーマ。demo にも同じファイル。

- `wp-content/themes/shinsei-kouki/inc/plugin-customize_mw-wp-form.php`
- `wp-content/themes/shinsei-kouki/inc/common_theme.php`
- `wp-content/themes/shinsei-kouki/assets/css/contact/contact.css`
- `wp-content/themes/shinsei-kouki/assets/js/contact/contact.js`

プラグイン。PHP 8.4 以降の非推奨（暗黙の nullable）を1行だけ修正済み。demo と本番の両方。

- `wp-content/plugins/mw-wp-form/classes/abstract/class.validation-rule.php`
- コンストラクタ引数は `?MW_WP_Form_Data $Data = null`

バックアップの `.php` をプラグイン配下に置かない。MW WP Form は同じフォルダの `*.php` を全部読むので、クラスの再定義でサイトが落ちる。

SCSS はローカルの原稿。公開側が読むのはコンパイル済みの `contact.css`。

## 4. 管理画面で足した本文

ファイルを上げただけでは、注意文もラジオも出ない。

### 固定ページ「お問い合わせ」

コードエディターのカスタム HTML。導入文の `</p>` の直後、`</div>` の前。

```html
<p class="contactNotice">商品・サービスの売り込み、取材、掲載のご提案などはお受けしておりません。<br>計量器に関するご相談のみ対応しております。</p>
```

視覚エディターで開くと、見出しや段落に変換されて `pageTitle` と `contactNotice` が外れる。確認画面・送信完了・入力エラーには入れない。

ショートコードは環境ごとに違う。ローカルの `23` を demo や本番へ貼ると、フォームが消えるか、別の固定ページの本文が出る。

### フォーム編集（左メニュー「お問い合わせ」）

「お問い合わせ種別」の直後、「お問い合わせ内容」の前。テキストモード。

ラジオの name は `inquiry_other`。最後の選択肢の文言は、PHP の判定と完全一致している。

`上記以外（営業・ご提案、取材、掲載など）`

## 5. 動作の要点

実装は `inc/plugin-customize_mw-wp-form.php`。

- 営業のとき、管理者メールの宛先を空にし、連番 `shinsei_kouki_inquiry_serial_number` は増やさない。
- データベース保存がオンだと、一度保存された直後に削除する。フックはフォーム番号に依存するため、存在する全フォームに付けている。
- 宛先が空だと送信失敗扱いになり、自動返信まで止まる。営業のときだけ、その1回を成功扱いにしている。
- 完了画面の文面差し替えは、ローカルの 23 だけを見ると demo（17）と本番（16）で通常文のままになる。送信直後のセッションを見て判定している。
- 管理者メールの件名欄に「※PHP側で連番処理」と入っている。通常送信は PHP が `【お問い合わせ】No.数字` に書き換える。営業の送信で削除が動かないと、この説明文が一覧のタイトルのまま残る。

## 6. 確認

demo と本番で、営業の区分は次のとおり。

- 自動返信はお断りの文面
- 問い合わせ一覧に残らない
- 完了画面は、担当者から連絡しない旨

本番は 2026-11-21 に送信確認し、問題なし。
